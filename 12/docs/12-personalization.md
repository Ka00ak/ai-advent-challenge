# День 12. Персонализация ассистента

## 1. Задача

Поверх модели памяти Дня 11 добавить персонализацию:

1. профиль пользователя;
2. предпочтения: стиль, формат, ограничения;
3. подключение профиля к каждому запросу;
4. пополнение профиля из диалога, а не только вручную;
5. проверка: одна и та же цепочка из 10 вопросов для каждого из 3 профилей
   (30 запросов), контекст сохраняется внутри цепочки;
6. фиксация числа соблюдённых ответов и номера первого нарушения в каждом
   профиле.

## 2. Место профиля в архитектуре

Профиль — **не слой памяти** и не часть LTM. Это отдельная сущность,
применяемая поверх STM/WM/LTM. Поэтому:

- файл `profiles/profiles.json` не входит в `MemoryBundle`;
- очистка STM/WM/LTM не удаляет профиль;
- профилей может быть несколько, активен ровно один;
- память не откатывает профиль (он глобальный для пользователя).

```text
profiles/profiles.json     ProfileState { active, profiles[] }
        │
        ▼
AppController::send_user_message
  ├─ learn_from_message(active_profile, user_text)
  ├─ assemble_prompt(profile = active)
  └─ LLM
```

## 3. Модель профиля

```rust
pub struct UserProfile {
    pub id: String,
    pub title: String,
    pub identity: ProfileIdentity,   // имя, роль, язык
    pub verbosity: Verbosity,        // brief | normal | detailed
    pub tone: Tone,                  // formal | neutral | informal
    pub format: ProfileFormat {      // code, lists, tables, emoji
        pub code: CodePolicy,        // with-code | no-code | neutral
        pub lists: bool,
        pub tables: bool,
        pub emoji: bool,
    },
    pub constraints: Vec<String>,
    pub preferences: Vec<LearnedPreference>, // история изменений
    pub source: ProfileSource,       // manual | dialogue | preset | migration
    pub revision: u32,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
}
```

`LearnedPreference` хранит `key`, `value`, `source`, `evidence` (цитату из
реплики), `confidence` и время. Это делает пополнение проверяемым: видно, из
какой фразы взялось предпочтение.

Встроенные профили создаются при первом запуске:

| ID | Объём | Тон | Код |
|---|---|---|---|
| `default` | обычный | нейтральный | по ситуации |
| `brief` | кратко | неформальный, на «ты» | без кода |
| `detailed` | подробно | формальный, на «вы» | с примерами кода |

## 4. Профиль в промпте

Порядок блоков:

```text
system (ядро)
system (## Персонализация)      ← профиль
system (LTM: профиль/проект/предпочтения)
system (LTM: релевантное)
system (WM)
system (STM summary)
messages (STM window)
user (текущая реплика)
tools
```

Блок персонализации содержит проверяемые требования:

```text
## Персонализация: предпочтения пользователя
Это настройки пользователя. Соблюдай их в каждом ответе; текущая явная просьба важнее профиля.

- Профиль: Кратко, без кода, неформально (brief)
- Тон: неформальный, обращайся на «ты»
- Объём: кратко, не более 80 слов
- Код: без кода, не приводи фрагменты кода
- Списки: не использовать
- Таблицы: не использовать
- Эмодзи: не использовать
- Ограничения: Без вступлений; Без эмодзи
```

`MemoryBreakdown.profile_tokens` учитывает блок отдельно; `total_tokens`
включает его. Приоритет: свежая реплика > WM > LTM > профиль.

## 5. Пополнение из диалога

`src/memory/personalization.rs::learn_from_message` — детерминированные
правила без сетевых запросов. Срабатывают только при наличии маркера
предпочтения («отвечай», «пиши», «используй», «предпочитаю», «запомни»,
«пожалуйста», «формат», «стиль») или прямой команды в начале реплики.

| Признак | Что меняется |
|---|---|
| «кратко», «коротко», «покороче», «без воды» | `verbosity = brief` |
| «подробно», «подробнее», «детально» | `verbosity = detailed` |
| «без кода», «не пиши код» | `format.code = no-code` |
| «с кодом», «пример кода» | `format.code = with-code` |
| «формально», «на вы», «официально» | `tone = formal` |
| «неформально», «на ты», «по-простому» | `tone = informal` |
| «списком», «без списков» | `format.lists` |
| «таблицей», «без таблиц» | `format.tables` |
| «без эмодзи», «с эмодзи» | `format.emoji` |
| «без вступлений», «без извинений», «только факты» | `constraints` |
| «меня зовут …», «я работаю …» | `identity.name/role` |
| «отвечай на английском/по-русски» | `identity.language` |

Последняя реплика выигрывает конфликт. Изменения применяются **до** сборки
промпта, поэтому действуют уже на текущий ответ. Вопрос («Как лучше отвечать
кратко?») не считается командой.

## 6. Проверка

Команда:

```sh
cargo run -- --data-dir ./data personalize --check \
  --out docs/results/personalization-YYYY-MM-DD.md \
  --json docs/results/personalization-YYYY-MM-DD.json
```

Что делает:

1. Берёт 3 профиля `brief`, `detailed`, `default` (или `--profiles id1,id2,...`).
2. Задаёт **одну и ту же цепочку из 10 вопросов** каждому профилю. Внутри
   цепочки STM сохраняется, поэтому вопросы идут как один диалог в чате;
   у каждого профиля свой контекст. Итого 3 × 10 = **30 запросов**.
3. Оценивает каждый ответ по предпочтениям профиля:
   - объём: ≤ 80 слов для `brief`, ≥ 70 для `detailed`;
   - тон: отсутствие «ты/тебе/слушай/второе лицо» для `formal`, наличие
     неформального обращения для `informal`;
   - код: блок кода / отсутствие кода;
   - списки, таблицы, эмодзи: наличие или отсутствие;
   - ограничение «без вступлений».
4. Считает соблюдённые ответы во всех цепочках, полностью соблюдённые
   профили и `first_violation` — номер первого ответа с нарушением в каждом
   профиле.
5. `--no-stability` включает короткий режим: по одному вопросу на профиль
   (3 запроса) вместо цепочки.
6. Пишет Markdown + JSON, `--check` возвращает код 4 при провале порогов.

Пороги: минимум 2 профиля; в каждом профиле ≥ 8/10 соблюдённых ответов;
полная цепочка (≥ 3 профиля × 10 вопросов, для 3 профилей — 30 запросов);
нет ошибок API. Короткий режим `--no-stability` (3 запроса) порог полной
цепочки не проходит и с `--check` вернёт код 4.

### Приложенные реальные прогоны

Исторические прогоны `deepseek-chat`, 2026-11-19, temperature 0.2 (старый
формат: один вопрос + серия в одном профиле):

| Прогон | Сравнение | Устойчивость |
|---|---|---|
| Основной, `detailed` | 2/2 | 10/10, первое нарушение — нет |
| Дополнительный, `brief` | 2/2 | 6/10, первое нарушение — ответ #2 |

Основной отчёт: `docs/results/personalization-2026-11-19.md`.
Дополнительный: `docs/results/personalization-2026-11-19-brief.md`.

Дополнительный прогон показывает реальную деградацию: в `brief`-профиле
модель на части ответов переходит в нейтральный тон, хотя объём и отсутствие
кода сохраняет. Это и есть измеряемая устойчивость, а не скрытый дефект.
Новый режим 3 × 10 запускается той же командой; формат отчёта содержит
отдельную таблицу цепочки для каждого профиля.

## 7. CLI и TUI

```text
profile list [--json]
profile show [ID] [--json]
profile use ID
profile add ID [--like default|brief|detailed] [--title ...] [правки]
profile set ID [правки]
profile delete ID
profile learn "текст"
personalize [--question ...] [--profiles ...]
            [--no-stability] [--out MD] [--json JSON] [--check]
```

TUI: экран `7 Профиль` — список профилей, предпочтения, история обучения;
`Enter`/`u` активирует выбранный профиль. Остальные действия — CLI.
Экран `4 Проверка` переключается клавишей `p` в режим **«Профили»**:
`r` — 10 вопросов подряд для каждого из 3 профилей (30 запросов), `Space` —
короткий режим (1 вопрос на профиль), `e` — первый вопрос цепочки, `s` —
сохранить MD/JSON, `d` — детали всех цепочек и первого нарушения.

## 8. Тесты

- `src/domain/profile.rs` — serde, пресеты, активный профиль, удаление.
- `src/memory/personalization.rs` — все оси обучения, конфликт «последняя
  реплика», отсутствие ложных срабатываний, блок промпта.
- `src/memory/prompt.rs` — порядок блока, токены, отсутствие блока без профиля.
- `src/experiment/personalization.rs` — fake-прогон 3 × 10 = 30 запросов,
  изоляция контекста профилей, детекторы нарушений, Markdown/JSON.
- `tests/controller.rs` — обучение из диалога, сохранение и переключение.
- `tests/cli.rs` — `profile list/use/learn`, `personalize --check`, отчёты.
- `tests/storage.rs` — roundtrip и битый `profiles.json`.
- `tests/tui.rs` — экран профиля и активация.

## 9. Ограничения

- Оценка предпочтений эвристическая: слова, код, списки, таблицы, тон.
  Семантические синонимы и «почти формальный» стиль могут оцениваться грубо.
- Один прогон и одна модель; результат зависит от температуры и версии.
- Профиль глобальный и не входит в снимки памяти.
- Fake-прогон проверяет механику, а не качество модели; он всегда помечен
  `fake` в отчёте.
