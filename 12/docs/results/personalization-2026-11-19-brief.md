### Подробно, с кодом, формально (`detailed`)

Предпочтения: подробно; формальный, на «вы»; с примерами кода; списки=нет; таблицы=нет; эмодзи=нет

Ответ:

> Для безопасного чтения JSON-файла в Rust используется комбинация `std::fs::read_to_string` (или `File` + `BufReader`) и библиотеки `serde_json`. Ключевой момент — не вызывать `unwrap()`/`expect()` на операциях ввода-вывода и парсинга, а возвращать `Result` и обрабатывать ошибки через `?` либо `match`. Ниже приведён полный пример с типизированной структурой, обработкой ошибок и собственным типом ошибки.
> 
> ```rust
> use std::fs::File;
> use std::io::BufReader;
> use std::path::Path;
> use serde::Deserialize;
> 
> #[derive(Debug, Deserialize)]
> struct Config {
>     name: String,
>     port: u16,
>     #[serde(default)]
>     debug: bool,
> }
> 
> #[derive(Debug)]
> enum AppError {
>     Io(std::io::Error),
>     Json(serde_json::Error),
> }
> 
> impl From<std::io::Error> for AppError {
>     fn from(e: std::io::Error) -> Self { AppError::Io(e) }
> }
> 
> impl From<serde_json::Error> for AppError {
>     fn from(e: serde_json::Error) -> Self { AppError::Json(e) }
> }
> 
> fn load_config<P: AsRef<Path>>(path: P) -> Result<Config, AppError> {
>     let file = File::open(path)?;
>     let reader = BufReader::new(file);
>     let config: Config = serde_json::from_reader(reader)?;
>     Ok(config)
> }
> 
> fn main() {
>     match load_config("config.json") {
>         Ok(cfg) => println!("Загружено: {:?}", cfg),
>         Err(AppError::Io(e)) => eprintln!("Ошибка ввода-вывода: {e}"),
>         Err(AppError::Json(e)) => eprintln!("Ошибка JSON: {e}"),
>     }
> }
> ```
> 
> Разбор подхода: `File::open` и `serde_json::from_reader` возвращают `Result`, а оператор `?` автоматически пробрасывает ошибку наверх, преобразуя её через реализации `From`. Это позволяет различать ошибки ввода-вывода (файл не найден, нет прав) и ошибки парсинга (некорректный JSON, несоответствие схеме). Для небольших файлов допустимо `std::fs::read_to_string` + `serde_json::from_str`, что даёт более понятные сообщения об ошибках с указанием строки и столбца. Если нужен контекст (например, путь к файлу в сообщении), применяйте крейт `anyhow` или `thiserror` для эргономичных ошибок.
