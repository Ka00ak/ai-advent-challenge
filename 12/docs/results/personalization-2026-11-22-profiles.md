### Подробно, с кодом, формально (`detailed`)

Предпочтения: подробно; формальный, на «вы»; с примерами кода; списки=нет; таблицы=нет; эмодзи=нет

Ответ:

> Для безопасного чтения JSON-файла в Rust используется крейт `serde_json` в сочетании с `std::fs`. Ключевой принцип — не вызывать `unwrap()` и `expect()` в местах, где ошибка возможна, а возвращать `Result` и обрабатывать все варианты отказа: отсутствие файла, ошибку ввода-вывода, некорректный JSON, несоответствие схеме. Ниже приведён полный пример с пользовательской обработкой ошибок.
> 
> ```rust
> use std::fs;
> use std::path::Path;
> use serde::Deserialize;
> 
> #[derive(Debug, Deserialize)]
> struct Config {
>     name: String,
>     port: u16,
>     enabled: bool,
> }
> 
> #[derive(Debug)]
> enum ConfigError {
>     Io(std::io::Error),
>     Parse(serde_json::Error),
> }
> 
> impl std::fmt::Display for ConfigError {
>     fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
>         match self {
>             ConfigError::Io(e) => write!(f, "ошибка чтения файла: {e}"),
>             ConfigError::Parse(e) => write!(f, "ошибка разбора JSON: {e}"),
>         }
>     }
> }
> 
> impl std::error::Error for ConfigError {}
> 
> impl From<std::io::Error> for ConfigError {
>     fn from(e: std::io::Error) -> Self {
>         ConfigError::Io(e)
>     }
> }
> 
> impl From<serde_json::Error> for ConfigError {
>     fn from(e: serde_json::Error) -> Self {
>         ConfigError::Parse(e)
>     }
> }
> 
> fn load_config(path: &Path) -> Result<Config, ConfigError> {
>     let content = fs::read_to_string(path)?;
>     let config: Config = serde_json::from_str(&content)?;
>     Ok(config)
> }
> 
> fn main() {
>     match load_config(Path::new("config.json")) {
>         Ok(cfg) => println!("Загружено: {:?}", cfg),
>         Err(e) => eprintln!("Не удалось загрузить конфигурацию: {e}"),
>     }
> }
> ```
> 
> Разбор примера: `fs::read_to_string` возвращает `io::Result<String>`, а `serde_json::from_str` — `serde_json::Result<T>`. Реализация `From` для обоих типов позволяет использовать оператор `?`, автоматически преобразуя ошибки в `ConfigError`. Это идиоматичный способ, при котором вызывающий код получает единый тип ошибки и может решать, как реагировать. Для более сложных случаев применяют крейт `thiserror` (сокращает шаблонный код) или `anyhow` (для приложений, где не нужна типизированная ошибка). Если файл большой, вместо `read_to_string` используют `serde_json::from_reader` с `BufReader`, чтобы не держать весь текст в памяти.
>
