# 06. UI-спецификация

## 1. Навигация

Вкладки приложения:

```text
Настройки | Память | Проверка | Токены | История | Ветки | API
```

- **Стратегии** Дня 10 удаляются: их место занимают «Память» (состав слоёв) и
  «Проверка» (ablation и очистка).
- «История» остаётся и явно подписана как STM.
- «Проверка» появляется только при наличии фикстуры; без неё — пустое состояние.

## 2. Вкладка «Память»

### 2.1. Верхняя сводка

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Память                                                               │
│ STM: 34 сообщения · в окне 8 · 620 ток.                              │
│ WM:  7 пунктов · 160 ток.        LTM: 15 записей · 310 ток.         │
│ [Импортировать facts Дня 10] [Аудит] [Экспорт памяти]                │
└──────────────────────────────────────────────────────────────────────┘
```

Кнопка миграции:

- disabled, если `lab10.facts.v1` не найден; подпись «Facts Дня 10 не найдены»;
- после импорта показывает отчёт: `найдено 12 · добавлено 12 · обновлено 0 ·
  пропущено 0`;
- повторный запуск: `добавлено 0`, значения не дублируются.

### 2.2. Три колонки

На широком экране — 3 колонки, на узком — подвкладки. Пустые состояния
обязательны.

```text
┌─ Краткосрочная (STM) ─────┐ ┌─ Рабочая (WM) ────────────┐ ┌─ Долговременная (LTM) ──┐
│ текущий диалог            │ │ текущая задача            │ │ профиль, решения, знания│
│ 34 сообщения · 620 ток.   │ │ 7 пунктов · 160 ток.     │ │ 15 записей · 310 ток.   │
│ [Очистить]                │ │ [Завершить задачу]        │ │ [Очистить]              │
├───────────────────────────┤ ├───────────────────────────┤ ├─────────────────────────┤
│ ── сводка ──              │ │ Задача: смета маркетинга  │ │ ★ project.name          │
│ Обсуждали проект…         │ │ План:                     │ │   «Атлас»               │
│                           │ │ 1 [x] Собрать каналы      │ │   project · pinned      │
│ ── окно (8) ──            │ │ 2 [ ] Оценить каналы      │ │                         │
│ user: Уточнение: бюджет…  │ │ …                         │ │ decision.database       │
│ assistant: Учту…          │ │ [+ Добавить]              │ │ PostgreSQL…             │
│ …                         │ │                           │ │ decision · 13.11       │
│ [Открыть историю]         │ │                           │ │                         │
└───────────────────────────┘ └───────────────────────────┘ └─────────────────────────┘
```

### 2.3. Карточка записи

Каждая карточка (`MemoryItemCard.vue`) показывает:

- ключ и значение;
- бейдж типа (`profile`, `decision`, `plan`…);
- источник (`router`, `tool`, `user`, `migration`);
- время обновления;
- для LTM: `pinned` (★), `confidence`, версию (если есть superseded);
- меню действий.

Действия:

| Кнопка | STM | WM | LTM |
|---|---|---|---|
| Изменить | — | да | да |
| Удалить | — | да | да (с подтверждением) |
| Pin | — | — | да |
| В LTM | — | да (pending) | — |
| В задачу | — | — | да (создаёт ссылку) |
| В STM | — | — | — (STM только сообщения) |
| Done / Active | — | да | — |
| Смотреть историю версий | — | — | да |

«В LTM» из WM открывает диалог выбора `kind`, `key`, `value` и создаёт
`PendingWrite` (даже в режиме `auto` — ручное действие всегда подтверждается
явно).

## 3. Очередь подтверждений

Блок над колонками, если `pending.length > 0`:

```text
┌─ Ждут подтверждения (2) ─────────────────────────────────────────────┐
│ project.deadline · knowledge · R3                                    │
│ Было: 15 декабря 2026 → Станет: 20 декабря 2026                     │
│ [Принять] [Отклонить] [Изменить] [Слой: LTM ▾]                       │
├──────────────────────────────────────────────────────────────────────┤
│ budget.marketing · knowledge · R3 · stale (8 дней)                   │
│ Было: 120 000 ₽ → Станет: 150 000 ₽                                  │
│ [Принять] [Отклонить] [Изменить] [Слой: LTM ▾]                       │
└──────────────────────────────────────────────────────────────────────┘
```

Правила:

- «Принять» применяет запись, пишет аудит, убирает из очереди;
- «Отклонить» удаляет, пишет аудит с причиной;
- смена слоя на WM применяет сразу и убирает из очереди;
- «Изменить» открывает форму; сохранение применяет;
- пустая очередь: «Все записи подтверждены»;
- stale-бейдж, если старше 7 дней.

## 4. Аудит

Боковая панель или модалка по кнопке «Аудит»:

```text
10:12:01  LTM  create  project.name   «Атлас»          router R4
10:12:05  WM   create  task.goal      Смета маркетинга router R2
10:12:09  LTM  pending budget.marketing 150 000 ₽       router R3
10:12:30  LTM  accept  budget.marketing 150 000 ₽       user
10:13:00  WM   update  plan.1         done              user
```

- фильтры: слой, источник, операция;
- экспорт JSON;
- лимит 200 событий; старые вытесняются;
- значения секретов — `***`.

## 5. Вкладка «Токены»

Дополняется блоком «Память в текущем запросе»:

```text
Запрос #3 · strategy: layers (stm+wm+ltm)
┌──────────────────────────────────────────────┐
│ system        ████ 420                        │
│ LTM профиль   ██ 180                          │
│ LTM релевант. █ 120                           │
│ WM            █ 160                           │
│ STM сводка    ▌ 90                            │
│ STM окно      ██████ 620                      │
│ текущий вопрос ▌ 50                           │
│ tools         ███ 310                         │
├──────────────────────────────────────────────┤
```

Таблица по запросам сессии: дата, слой-блоки, total, cost. Данные берутся из
`LlmExchange.memory`; если разбивки нет (старые записи) — прочерк.

## 6. Вкладка «Проверка»

### 6.1. Подготовка

```text
Контрольный диалог: 34 сообщения · 18 вопросов (6 STM / 6 WM / 6 LTM)
Окно STM: 8 · извлечение: local · режим: полный [quick/full]
[Загрузить фикстуру] [Запустить 7 конфигураций] [Отмена]
```

- «Загрузить фикстуру» заполняет STM/WM/LTM детерминированно (без API), чтобы
  прогон был воспроизводим;
- текущая память пользователя не уничтожается: фикстура работает в отдельном
  прогоне (in-memory snapshot) и не сохраняется поверх рабочих слоёв;
- предупреждение о стоимости: «≈ 126 запросов в полном режиме».

### 6.2. Прогресс

```text
Прогон: stm+wm  ·  вопрос 7/18  ·  всего 43/126
[████████░░░░░░░░]  [Отмена]
```

Отмена прерывает текущий запрос и не сохраняет частичный отчёт.

### 6.3. Результаты: ablation

```text
Конфигурация   LTM   WM    STM   System  Tools  Total   STM✓  WM✓  LTM✓  Всего
none           0     0     0     420     310    780     0     0    0      0/18
stm            0     0     620   420     310    1400    6     0    0      6/18
wm             0     160   0     420     310    940     0     6    0      6/18
ltm            300   0     0     420     310    1080    0     0    6      6/18
stm+wm         0     160   620   420     310    1560    6     6    0      12/18
stm+wm+ltm     300   160   620   420     310    1860    6     6    6      18/18
```

`Total` включает текущую реплику probe (~50 токенов), она одинакова во всех
конфигурациях и поэтому не показана отдельной колонкой.

```text

LTM    300              300                           6/6

```


### 6.6. Отчёт

Кнопки: «Скачать Markdown», «Скачать JSON», «Скопировать вывод».
В отчёт попадают: дата, модель, настройки, таблицы, список неотвеченных
вопросов, стоимость, выводы.

## 7. Вкладка «История»

- Подпись: «Краткосрочная память (STM). Полная история, окно влияет только на
  запрос».
- Экспорт/импорт как в Дне 10.
- При импорте: предупреждение «Курсор маршрутизации и очередь подтверждений
  будут сброшены; WM и LTM останутся, если вы их не очистите».
- Кнопка «Очистить STM» дублируется здесь и в колонке STM; обе требуют
  подтверждения.

## 8. Вкладка «Настройки»

Секция «Память»:

| Поле | Значения | По умолчанию |
|---|---|---|
| Режим извлечения | `local` / `llm` | `local` |
| Подтверждение LTM | `confirm` / `auto` | `confirm` |
| Окно STM | 4–20 | 8 |
| Бюджет STM | 400–4000 | 1600 |
| Сводка STM | вкл/выкл | вкл |
| Бюджет WM | 100–1000 | 320 |
| Top-K LTM | 1–20 | 8 |
| Бюджет LTM (релевантное) | 100–1200 | 360 |

Опасная зона: «Очистить STM», «Очистить WM», «Очистить LTM», «Сбросить всё».
Каждая кнопка — с диалогом и перечнем последствий. Очистка LTM также очищает
pending (он относится только к LTM); STM и WM при этом не меняются.

## 9. Вкладка «Ветки»

- Checkpoint показывает состав: `STM 34 · WM 7 · LTM 15 · pending 2`.
- Создание веток клонирует все пять частей.
- Переключение заменяет всё; бейдж «активная ветка».
- Сравнение веток (P2): количество записей по слоям.

## 10. Вкладка «API»

- Бейджи: `chat`, `summary`, `memory`.
- Для `memory` показывается: режим (`local/llm`), число кандидатов, запись в
  какой слой, ошибка, если был откат.
- Фильтр по виду запроса.

## 11. Состояния и ошибки

| Состояние | UI |
|---|---|
| Слой пуст | «Пока пусто» + подсказка, что сюда попадёт |
| Загрузка | скелетон колонки, не блокирует остальные |
| Ошибка чтения слоя | красный баннер с текстом, кнопка «Сбросить слой» |
| Переполнение хранилища | жёлтый баннер «Не удалось сохранить LTM: хранилище заполнено» |
| Pending stale | серый бейдж «stale N дней» |
| Эксперимент идёт | прогресс + отмена, остальные вкладки доступны |
| Нет API-ключа | прогон не стартует, ссылка в настройки |
| Ссылка WM потеряна | бейдж «LTM-запись удалена» |

## 12. Доступность и поведение

- Все destructive-действия — только через подтверждение.
- Кнопки имеют текстовые подписи, не только иконки.
- Фокус после закрытия модалки возвращается на инициатора.
- Поиск по LTM — по key/value/tags, debounce 150 мс.
- Списки не перерисовывают порядок при каждом обновлении: сортировка стабильна.
