# 01. Требования

Приоритеты: **P0** — без этого день не сдан; **P1** — нужно для полноты;
**P2** — можно отложить.

Все ID используются в `09-tasks.md`, `08-test-plan.md` и
`11-traceability.md`.

## A. Слои и хранилища

| ID | Требование | Приоритет | Приёмка |
|---|---|---|---|
| FR-1 | **STM** хранит сообщения диалога и сводку вытесненной части в отдельных файлах. | P0 | `stm/conversation.json`, `stm/summary.json`; очистка STM не трогает WM/LTM |
| FR-2 | **WM** хранит состояние текущей задачи: цель, план, статус, выбранные варианты, открытые вопросы. | P0 | `wm/working.json`; `WmItem` имеет `kind`, `status`, `updatedAt` |
| FR-3 | **LTM** хранит профиль, проект, предпочтения, решения, знания, глоссарий. | P0 | `ltm/ltm.json`; `LtmRecord.key` уникален среди активных |
| FR-4 | Ни один слой не пишет в файл другого слоя. | P0 | тест: `clearLtm()` не меняет STM/WM; `saveWorking()` не трогает LTM |
| FR-5 | Каждый слой очищается независимо, с подтверждением и объяснением последствий. | P0 | TUI/CLI `memory clear --layer`; остальные слои на месте |
| FR-6 | Все слои сохраняются атомарно и восстанавливаются; битый JSON не роняет приложение. | P0 | temp+ATOMIC_MOVE; parse возвращает `Result`/`LoadError`; бэкап `.bak` |
| FR-7 | Полная история STM не удаляется при усечении промпта. | P0 | окно влияет только на запрос, файл истории полный |
| FR-8 | Data-dir настраивается; по умолчанию XDG, для демо — `./data`. | P1 | `--data-dir`, `LAB11_HOME`; файлы создаются при старте |
| FR-9 | Одновременный запуск двух экземпляров на одном data-dir блокируется lock-файлом. | P1 | второй процесс завершается с понятной ошибкой |
