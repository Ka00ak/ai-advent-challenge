# kimi-k3 — задача 7

**Задача:**
Дан массив целых чисел. Найдите максимальную сумму подмассива (задача Кадане). А теперь усложнение: массив по кругу (последний элемент соседствует с первым) — найдите максимальную сумму непустого циклического подмассива. В чём подвох, если все числа отрицательные?

**Ответ:**
## 1. Классическая задача Кадане

**Идея:** идём слева направо и поддерживаем `cur` — максимальную сумму подмассива, **заканчивающегося** в текущей позиции. Для каждого элемента выбор простой: либо продлить предыдущий подмассив, либо начать новый с текущего элемента.

```python
def max_subarray(nums):
    best = cur = nums[0]
    for x in nums[1:]:
        cur = max(x, cur + x)   # начать заново или продолжить
        best = max(best, cur)
    return best
```

Время `O(n)`, память `O(1)`.

⚠️ Частая ошибка — инициализировать `cur = 0` и писать `cur = max(0, cur + x)`. Это неявно разрешает **пустой** подмассив, и для массива из одних отрицательных чисел вы получите `0` вместо максимального элемента.

## 2. Циклический вариант

**Ключевое наблюдение.** Любой циклический подмассив — это один из двух случаев:

1. **Обычный** подмассив (не «переходит через край») → это ответ классического Кадане `max_sum`.
2. **Обертывающийся**: суффикс + префикс. Но тогда его *дополнение* — обычный подмассив посередине, и:
   `сумма(обертывающегося) = total − сумма(середины)`.
   Чтобы максимизировать его, надо **минимизировать** середину, т.е. найти подмассив с минимальной суммой — тем же Кадане, только с `min`.

Ответ: `max(max_sum, total − min_sum)` — обе величины считаются за один проход.

```python
def max_circular_subarray(nums):
    total = nums[0]
    max_sum = cur_max = nums[0]   # обычный Кадане
    min_sum = cur_min = nums[0]   # Кадане на минимум
    for x in nums[1:]:
        cur_max = max(x, cur_max + x)
        max_sum = max(max_sum, cur_max)
        cur_min = min(x, cur_min + x)
        min_sum = min(min_sum, cur_min)
        total += x
    if max_sum < 0:          # все числа отрицательные
        return max_sum
    return max(max_sum, total - min_sum)
```

**Пример:** `[5, -3, 5]` → обычный максимум `7`, но `total − min_sum = 7 − (−3) = 10` (берём `[5] + [5]` через край). Ответ: `10`.

## 3. Подвох с отрицательными числами

Если **все** числа отрицательные, то подмассив с минимальной суммой — это **весь массив целиком**. Тогда:

```
total − min_sum = total − total = 0
```

Ноль — это сумма **пустого** подмассива («взять всё через край, вычтя весь массив» = ничего не взять). А по условию подмассив должен быть **непустым**. Наивная формула `max(max_sum, total − min_sum)` вернёт `0` — неправильно.

Корректный ответ для всех отрицательных — **максимальный (наименее отрицательный) элемент**, т.е. результат обычного Кадане. Поэтому нужна явная проверка:

```python
if max_sum < 0:      # эквивалентно: if total == min_sum
    return max_sum
```

Например, `[-3, -2, -3]` → правильный ответ `-2`, а не `0`.

Заметим, что если в массиве есть хотя бы один неотрицательный элемент, ловушка не срабатывает: минимальный подмассив гарантированно *собственный* (не весь массив), и `total − min_sum` соответствует реальному непустому обертывающемуся подмассиву.

## Проверка на тестах

| Массив | Обычный Кадане | Циклический | Комментарий |
|---|---|---|---|
| `[5, -3, 5]` | 7 | **10** | обертка через край |
| `[1, -2, 3, -2]` | 3 | **3** | обычный выигрывает |
| `[8, -1, 3, 4]` | 14 | **15** | `[3,4]` + `[8]` |
| `[-3, -2, -3]` | −2 | **−2** | ловушка с нулём |
| `[5]` | 5 | **5** | вырожденный случай |

**Итог:** время `O(n)`, память `O(1)`, один проход; единственный краевой случай — все элементы отрицательные, где формула с `total − min_sum` незаконно «разрешает» пустой подмассив.
