# kimi-k3.1.pro — задача 7

**Задача:**
Дан массив целых чисел. Найдите максимальную сумму подмассива (задача Кадане). А теперь усложнение: массив по кругу (последний элемент соседствует с первым) — найдите максимальную сумму непустого циклического подмассива. В чём подвох, если все числа отрицательные?

**Ответ:**
Будем считать подмассив **непрерывным и непустым**, а для кругового массива — длиной не больше `n`, то есть без повторного прохождения по элементам.

### 1. Обычный массив: алгоритм Кадане

Пусть `cur` — максимальная сумма подмассива, заканчивающегося в текущем элементе. Для очередного `x` есть два варианта:

- продолжить предыдущий подмассив: `cur + x`;
- начать новый подмассив с `x`.

```python
def kadane(a):
    if not a:
        raise ValueError("Массив должен быть непустым")

    cur = best = a[0]
    for x in a[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)

    return best
```

Важно инициализировать переменные **первым элементом, а не нулём**: иначе для массива из отрицательных чисел алгоритм неправильно вернёт `0`, фактически выбрав пустой подмассив.

### 2. Круговой массив

Оптимальный подмассив может быть двух видов:

1. **Не переходит через границу.**  
   Тогда ответ уже найден обычным алгоритмом Кадане — обозначим его `max_sum`.

2. **Переходит через границу**, то есть состоит из суффикса и префикса массива.  
   Его дополнение до всего массива — обычный непрерывный подмассив. Поэтому:
   \[
   \text{сумма с переходом}=\text{total}-\text{сумма дополнения}.
   \]
   Чтобы максимизировать результат, нужно вычесть **минимальную сумму подмассива** `min_sum`. Её можно найти вариантом Кадане с `min`.

```python
def max_circular_subarray(a):
    if not a:
        raise ValueError("Массив должен быть непустым")

    total = a[0]

    cur_max = max_sum = a[0]
    cur_min = min_sum = a[0]

    for x in a[1:]:
        total += x

        cur_max = max(x, cur_max + x)
        max_sum = max(max_sum, cur_max)

        cur_min = min(x, cur_min + x)
        min_sum = min(min_sum, cur_min)

    # Все элементы отрицательные: кандидат total - min_sum недопустим.
    if max_sum < 0:
        return max_sum

    return max(max_sum, total - min_sum)
```

Например, для `[5, -3, 5]`:

- обычный максимум: `5 + (-3) + 5 = 7`;
- циклический: последний `5` + первый `5`, сумма `10`;
- ответ: `10`.

### В чём подвох с отрицательными числами?

Если все числа отрицательные, минимальный подмассив — это **весь массив**, поэтому:

```text
min_sum = total
total - min_sum = 0
```

Но этот `0` соответствует вычитанию всего массива, то есть **пустому подмассиву**, который запрещён. Без специальной проверки формула неправильно вернёт `0`.

Правильный ответ в этом случае — **максимальный элемент**, например:

```text
[-5, -2, -7]  →  -2
```

**Сложность:** `O(n)` по времени и `O(1)` дополнительной памяти.
