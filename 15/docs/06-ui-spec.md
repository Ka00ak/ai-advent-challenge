# 06. TUI-спецификация

## 1. Общее

- Минимальный терминал: **80×24**, рекомендуемый — **120×36**.
- UTF-8; опционально ASCII-режим (P2).
- Мышь не требуется; весь функционал доступен с клавиатуры.
- При старте: alternate screen, raw mode, скрытый курсор; при выходе/панике
  терминал восстанавливается.
- При resize layout пересчитывается, данные не теряются.
- Логи не пишутся в stdout: ошибки — модалка/баннер; API-лог — экран «API».

## 2. Каркас экрана

```text
┌ lab11 · deepseek-chat · ./data ─────────────────────── [busy: chat] ┐
│ 1 Чат  2 Память  3 Подтверждения(2)  4 Проверка                    │
│ 5 Настройки 6 API 7 Профиль 8 Состояния 9 Инварианты               │
├───────────────────────────────────────────────────────────────────┤
│                                                                   │
│                        активный экран                             │
│                                                                   │
├───────────────────────────────────────────────────────────────────┤
│ Tab фокус · ↑↓ выбор · Enter открыть · ? помощь · q выход          │
└───────────────────────────────────────────────────────────────────┘
```

- Заголовок: модель, data-dir, индикатор job.
- Строка вкладок: `0` — чат, `1…9` — остальные экраны; счётчик pending,
  активная вкладка выделена.
- Футер: контекстные клавиши + `q`.
- Модалки рисуются по центру поверх экрана.

## 3. Экран «Чат» (1)

```text
┌ 1 Чат · STM + WM + LTM + профиль ─────────────────────────────────┐
│ Профиль: brief · Кратко, без кода, неформально                    │
│ STM 34 сообщ. · окно 8 · WM 7 · LTM 15 · прошлый промпт: …        │
├───────────────────────────────────────────────────────────────────┤
│ Вы · #33                                                          │
│   Как лучше отвечать на вопросы по проекту?                       │
│ Ассистент · #34                                                   │
│   Коротко и по делу, без вступления.                              │
├───────────────────────────────────────────────────────────────────┤
│ > введите сообщение▏                                   0/500      │
└───────────────────────────────────────────────────────────────────┘
```

- Показывает переписку STM (user/assistant/tool); системные блоки скрыты.
- Каждый запрос идёт через контроллер: STM, WM, LTM и активный профиль
  применяются так же, как в CLI `chat`.
- `i`/`Enter` — захватить ввод; `Enter` — отправить; `Esc` — выйти из ввода.
- `↑/↓`, `PgUp/PgDn` — прокрутка истории; `g`/`G` — начало/конец.
- `c` — очистить STM (модалка), `e` — экспорт JSON, `I` — импорт JSON.
  При импорте предупреждение: cursor/pending сбрасываются, WM/LTM остаются.
- Во время ответа заголовок показывает `[busy: chat]`, ввод не отправляет
  второй запрос до завершения job.
- Первая строка — активный профиль; вторая — размеры слоёв и breakdown
  последнего промпта.
- Полная история STM показывается здесь же; отдельного экрана «История» нет.

## 4. Экран «Память» (2)

```text
┌ Краткосрочная (STM) ──────┐┌ Рабочая (WM) ──────────────┐┌ Долговременная (LTM) ────┐
│ 34 сообщения · 8 в окне   ││ 7 пунктов · 160 ток.        ││ 15 записей · 310 ток.    │
│ [c] очистить              ││ [c] завершить задачу        ││ [c] очистить             │
├───────────────────────────┤├─────────────────────────────┤├──────────────────────────┤
│ ── сводка ──              ││ Задача: смета маркетинга    ││ ★ project.name           │
│ Обсуждали проект…         ││ План:                       ││   «Атлас»               │
│ ── окно (8) ──            ││ 1 [x] Собрать каналы        ││   project · pinned      │
│ user: Уточнение: бюджет…  ││ 2 [ ] Оценить каналы        ││                         │
│ assistant: Учту…          ││ …                           ││ decision.database       │
│ …                         ││                             ││ PostgreSQL…             │
└───────────────────────────┘└─────────────────────────────┘└──────────────────────────┘
```

- Фокус: `Tab`/`Shift+Tab` между колонками; активная рамка цветом.
- `↑/↓`, `PgUp/PgDn` — прокрутка списка колонки.
- `Enter` — модалка записи: key, value, kind, source, даты, confidence,
  версия, причина (`R4 · устойчивый факт`).
- Действия по фокусу:
  - STM: `c` — очистить (модалка), `Enter` — сообщение целиком;
  - WM: `a` добавить, `e` изменить, `d` удалить, `p` pin (нет), `m` → LTM,
    `c` завершить задачу;
  - LTM: `a`, `e`, `d`, `p` pin, `m` → WM, `c` очистить.
- `m` открывает выбор целевого слоя и `kind`; WM→LTM создаёт pending.
- Поиск по LTM: `/`, ввод подстроки, `Esc` сброс.
- Пустой слой: «Пока пусто» + подсказка.

## 5. Экран «Подтверждения» (3)

```text
┌ Ждут подтверждения (2) ───────────────────────────────────────────┐
│ > project.deadline · knowledge · R3                                │
│   Было: 15 декабря 2026 → Станет: 20 декабря 2026                 │
│                                                                    │
│   budget.marketing · knowledge · R3 · stale (8 дней)              │
│   Было: 120 000 ₽ → Станет: 150 000 ₽                              │
├────────────────────────────────────────────────────────────────────┤
│ Детали: source=router, message #27, reason="обновление ключа"      │
│ [y] принять  [n] отклонить  [e] изменить  [l] сменить слой         │
└────────────────────────────────────────────────────────────────────┘
```

- `y` — применить, удалить pending, аудит `accept`;
- `n` — отклонить, аудит `reject`;
- `e` — редактировать key/value/kind, затем `Enter` — применить;
- `l` — выбор `LTM/WM`; WM применяется сразу;
- пусто: «Все записи подтверждены»;
- stale-бейдж, если старше 7 дней;
- `g`/`G` — начало/конец списка.

```text
┌ Контрольный диалог: 34 сообщения · 18 probe (6/6/6) ───────────────┐
│ Режим: ( ) quick  (•) full      Окно STM: 8                        │
│ Конфигурации: [x] none [x] stm [x] wm [x] ltm [x] stm+wm [x] all   │
│ Очистка: [ ] включить (3 прогона)                                  │
│ [r] запустить   [Esc] отмена   запросов: ~180                      │
├────────────────────────────────────────────────────────────────────┤
│ Прогресс: stm+wm · вопрос 7/18 · 43/126 · probe-07 ✓              │
│ API: 43/126 · prompt 52 140 · completion 3 210 · $0.014200 · usage │
│ [██████████░░░░░░░░░░] 34%                                         │
├────────────────────────────────────────────────────────────────────┤
│ Конфигурация  LTM  WM   STM  System Tools Total  S✓ W✓ L✓ Всего   │
│ none           0    0     0    420    310   780  0  0  0   0/18   │
│ stm            0    0   620    420    310  1400  6  0  0   6/18   │
│ …                                                                  │
├────────────────────────────────────────────────────────────────────┤
│ [s] сохранить отчёт MD/JSON   [d] открыть детали                  │
└────────────────────────────────────────────────────────────────────┘
```

- `Space` — переключить чекбокс; `↑/↓` — выбор; `r` — запуск.
- Во время прогона экран обновляется событиями, TUI остаётся отзывчивым;
  строка API показывает число завершённых запросов, prompt/completion-токены,
  оценку стоимости, источник (`usage` или `оценка`) и счётчик ошибок.
  `Esc`/`q` — отмена (частичный отчёт не сохраняется).
- После завершения: таблицы ablation, вклад слоёв, матрица очистки,
  неотвеченные вопросы.
- `s` — диалог пути; по умолчанию
  `docs/results/experiment-YYYY-MM-DD.md` и `.json`.
- `d` — детали probe: вопрос, ожидание, ответ, ключевые слова.

### Режим «Профили» (`p`)

Вкладка «Проверка» имеет второй режим — проверку персонализации. `p`
переключает «Ablation памяти» ↔ «Профили».

```text
┌ Проверка профилей ─────────────────────────────────────────────────┐
│ Режим: Профили [p → ablation] · цепочка 10 вопросов на профиль     │
│ Профили: brief · detailed · default (3 профиля)                    │
│ Первый вопрос: Как в Rust безопасно прочитать JSON-файл…           │
│ Цепочка: вкл · 10 вопросов × 3 профиля = 30 запросов               │
│ Прогресс: цепочка · brief · 3/10 · 3/30 ✓                          │
│ [r] запустить · [Space] цепочка · [e] первый вопрос                │
│ [s] отчёт · [d] детали · [i] импорт                                │
├────────────────────────────────────────────────────────────────────┤
│ Соблюдено ответов: 30 из 30 · профилей полностью: 3 из 3           │
│ brief      10/10  кратко; неформ.; без кода…   первое: нет         │
│ detailed   10/10  подробно; форм.; с кодом…    первое: нет         │
│ default    10/10  обычный; нейтральный…        первое: нет         │
│ Пороги пройдены: персонализация подтверждена                       │
└────────────────────────────────────────────────────────────────────┘
```

- `r` — одна и та же цепочка из 10 вопросов каждому из 3 профилей.
  STM сохраняется внутри цепочки, поэтому вопросы идут как один диалог;
  у каждого профиля свой контекст. Итого 30 запросов.
- `Space` — короткий режим (1 вопрос на профиль, 3 запроса).
- `e` — первый вопрос цепочки; остальные 9 остаются стандартными.
- `s` — сохранить `docs/results/personalization-YYYY-MM-DD.md/.json`.
- `d` — детали: все ответы каждой цепочки, проверки (объём, тон, код,
  списки, таблицы, эмодзи) и номер первого нарушения.
- Прогон идёт в фоновом потоке; `q`/`Ctrl+C` отменяет.

## 7. Экран «Настройки» (5)

Форма (поля, `Tab` — фокус, `Enter` — редактировать, `s` — сохранить):

| Поле | Значения | По умолчанию |
|---|---|---|
| Base URL | строка | `https://api.deepseek.com` |
| Model | строка | `deepseek-chat` |
| Temperature | 0..2 | 0.2 |
| Max tokens | число/пусто | пусто |
| Max iterations | 1..12 | 6 |
| Extraction | `local`/`llm` | `local` |
| Approval | `confirm`/`auto` | `confirm` |
| STM window | 4..20 | 8 |
| STM max tokens | 400..4000 | 1600 |
| STM summary | on/off | on |
| WM max tokens | 100..1000 | 320 |
| LTM top-K | 1..20 | 8 |

Опасная зона: `Очистить STM/WM/LTM`, `Сбросить всё` — только через модалку.
Ключ API не редактируется в TUI; показывается источник (`env:DEEPSEEK_API_KEY`)
и маска.

## 8. Экран «API» (6)

Одна строка журнала — **один HTTP-запрос** к модели (включая запросы
tool-loop, LLM-извлечение и запросы эксперимента).

```text
┌ HTTP-запросы ──────────────────────┐┌ Детали запроса ─────────────────────┐
│ all (f) · 3 · ошибок 0             ││ chat · deepseek-chat · HTTP 200     │
│ #  время    kind   HTTP  prompt/comp││ POST …/chat/completions             │
│ > 1 10:12:34 chat   200   1950/120  ││ prompt 1950 · completion 120 · …    │
│   2 10:12:30 memory 200   380/60    ││ system 420 · профиль 84 · LTM …      │
│   3 10:12:28 chat   200   1500/90   ││ STM 620 · вопрос 50 · tools 310      │
│                                     │├─────────────────────────────────────┤
│                                     ││ [Запрос] Ответ      Tab/←→          │
│                                     ││ {                                   │
│                                     ││   "model": "deepseek-chat",          │
│                                     ││   "messages": […]                    │
│                                     ││ }                                   │
└─────────────────────────────────────┘└─────────────────────────────────────┘
```

- Экран двухпанельный: слева список HTTP-запросов, справа сразу детали
  выделенного запроса. Модальное окно не нужно.
- `↑/↓`, `g/G` — выбор запроса, когда фокус в списке; правая панель
  обновляется сразу.
- `Tab` — переключение фокуса **список ↔ тело запроса/ответа**; `Esc` из тела
  возвращает к списку.
- Сводка справа: kind, модель, HTTP-статус, длительность, prompt/completion/
  total, стоимость, размеры, разбивка токенов по блокам (system, профиль,
  LTM, WM, STM, текущий вопрос, tools) и слои LTM/WM/STM.
- `←`/`→` — переключение **«Запрос» / «Ответ»**; JSON подсвечивается:
  ключи, строки, числа и `true/false/null` разными стилями (в `NO_COLOR` —
  жирный/подчёркнутый текст).
- В фокусе тела `↑/↓` прокручивают JSON построчно, `PgUp/PgDn` — быстро,
  `Home`/`End` — начало/конец.
- `f` — фильтр all/chat/memory/error; `e` — экспорт журнала JSON.
- Секреты в телах маскируются (`***`), API-ключ в журнал не попадает.
- Запросы эксперимента появляются в журнале **по мере выполнения**; сводная
  строка прогресса убирается, как только приходят детальные HTTP-записи.

## 9. Экран «Состояния» (8)

```text
┌ Маршрут ──────────────────────────────────────────────────────────┐
│ [1 planning] → [2 execution] → [3 validation] → [4 done]          │
│ Этап: Выполнение · шаг 1/1 · статус: выполняется                   │
│ Текущий шаг: Выполнение плана                                     │
│ Ожидаемое действие: Выполнить утверждённый план…                  │
├ Диалог задачи · контекст сохраняется ─────────────────────────────┤
│ Вы · #1                                                          │
│   Подготовить отчёт                                              │
│ Ассистент · planning · #2                                        │
│   1. Собрать данные                                              │
│   2. Подготовить отчёт                                           │
│ Ассистент · execution · #3                                       │
│ Ассистент · validation · #4                                      │
├ Сообщение ───────────────────────────────────────────────────────┤
│ > i или Enter — написать агенту                                  │
└──────────────────────────────────────────────────────────────────┘
```

- `i`/`Enter` — захватить поле ввода сообщения; `Enter` — отправить.
- Задача выглядит как чат: реплики пользователя и ответы ассистента по
  этапам. Последние реплики передаются в контекст следующих запросов.
- Агент проходит этапы `planning → execution → validation → done` тремя
  запросами к LLM; каждый этап фиксируется в `TaskState`.
- Переход выполняет код после проверки предусловия: план из ≥ 2 шагов,
  непустой результат реализации, явный `ВЕРДИКТ: OK`.
- `p`/`Space` — пауза/продолжить; статус и подпись меняются сразу.
- `r` — сброс задачи и чата с подтверждением.
- `↑↓`, `PgUp/PgDn`, `g/G`, `Home/End` — прокрутка чата задачи.
- Пока задача активна, новое сообщение не отправляется. После завершения
  можно дописать следующее — начнётся новый цикл с сохранённым контекстом.
- История чата задачи хранится в `<data-dir>/task/session.json`.

### Экран «Инварианты» (9)

```text
┌ 9 Инварианты · жёсткие ограничения ───────────────────────────────┐
│ Инварианты проекта: 5 активных из 5                                │
│ Хранятся отдельно от диалога · изменения только явной командой      │
│ Попыток нарушения/обхода: 12 · заблокировано: 2 · probe: 10        │
├ Список · c/Enter изменить · d история · a аудит · p probe ────────┤
│ ● [архитектура] arch.local-rust-tui · ревизия 1                    │
│ ● [техническое решение] decision.postgresql · ревизия 1            │
│ ● [стек] stack.rust-only · ревизия 1                               │
├ Детали и последнее изменение ─────────────────────────────────────┤
│ stack.rust-only · стек · активен                                   │
│ Правило: production-код только на Rust 2024                        │
│ Код ищет признаки: python; javascript; golang; …                   │
└───────────────────────────────────────────────────────────────────┘
```

- `↑↓`, `PgUp/PgDn`, `g/G` — выбор инварианта.
- `c`/`Enter`/`e` — явная команда изменения: заголовок → правило →
  признаки нарушения через `;` → причина. Признаки можно очистить, чтобы
  старые фразы не продолжали блокировать запросы. Это не диалог с
  ассистентом; изменение фиксируется как «было → стало».
- `d` — история изменений выбранного инварианта.
- `a` — аудит конфликтов, попыток обхода и заблокированных ответов.
- `p` — прогнать 10 формулировок обхода без сети; результат и счётчик
  отображаются в шапке и аудите.
- Инварианты входят в каждый запрос чата и каждого этапа задачи отдельным
  system-блоком после профиля.

## 10. Модалки и ввод

| Модалка | Клавиши |
|---|---|
| Подтверждение | `y`/`n`, `Esc` |
| Редактирование записи | `Tab` поля, `Enter` сохранить, `Esc` отмена |
| Ввод пути | текстовое поле, `Enter`, `Tab` — автодополнение (P2) |
| Выбор слоя/типа | `↑/↓`, `Enter`, `Esc` |
| Ошибка | `Enter`/`Esc` закрыть |
| Помощь (`?`) | прокрутка, `Esc` |

Ввод: UTF-8, backspace, стрелки, Home/End, вставка (bracketed paste P2).
Длина ограничена 500 символами, счётчик в углу. Длинный текст переносится по
ширине окна; окно расширяется под терминал, вьюпорт следует за курсором,
курсор подсвечивается и выставляется системный. Это важно для правил
инвариантов и причины изменения: они не помещаются в одну строку.

## 11. Состояния

| Состояние | TUI |
|---|---|
| Пустой слой | «Пока пусто» + подсказка |
| Загрузка | заголовок `[busy: chat]`, действия заблокированы |
| Ошибка файла | красный баннер, `r` — reset слоя (с подтверждением) |
| Нет API-ключа | модалка с инструкцией по env |
| Lock занят | экран ошибки при старте, код 2 |
| Pending stale | серый бейдж |
| Ссылка потеряна | бейдж «LTM-запись удалена» |
| Узкий терминал | предупреждение, минимальный layout |

## 13. Доступность и поведение

- Все destructive-действия — через подтверждение.
- Клавиши имеют текстовые подписи в футере; `?` — полная справка.
- Цвет не единственный носитель смысла: статусы дублируются текстом.
- При `NO_COLOR` — монохромная тема.
- TUI не печатает stack trace; ошибки — короткий текст + подсказка.
