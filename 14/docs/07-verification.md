## 1. Гипотезы

## 6. Формулы токенов

Фиксируются:

```text
system, ltm_profile, ltm_relevant, wm, stm_summary, stm, current, tools, total
```

Прямой вклад:

```text
LTM = ltm_profile + ltm_relevant
WM  = wm
STM = stm_summary + stm
```

Инкремент:

```text
ΔLTM = total(stm+wm+ltm) − total(stm+wm)
ΔWM  = total(stm+wm)     − total(stm)
ΔSTM = total(stm)        − total(none)
```

`current` одинаков во всех конфигурациях и на дельты не влияет.

Проверка: `ΔLTM ≈ LTM-блоки` ±10 %.

Экономия:

```text
saved = total(full) − total(stm+wm+ltm)
saved_ratio = saved / total(full)
```

Точные токены — из `usage.prompt_tokens`, если провайдер вернул; оценка — в
отдельной колонке. Стоимость — по `ModelProfile`.

## 7. Прогон очистки

Старт — `stm+wm+ltm` с фикстурой.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | baseline | 18/18 (допуск ≥16) |
| 2 | очистить STM | падают S1–S6, W/L остаются |
| 3 | очистить WM | падают W1–W6, S/L остаются |
| 4 | очистить LTM | падают L1–L6, S/W остаются |

Правила:

- STM: удалить сообщения и summary, `meta.processed_messages=0`; WM/LTM/pending
  не меняются.
- WM: удалить пункты, `task_id=None`; STM/LTM/pending не меняются.
- LTM: удалить записи **и pending** (pending относится к LTM); STM/WM не
  меняются. `ref_ltm_id` в WM становится «потерянным».

Каждый шаг — на копии baseline, не поверх предыдущей очистки.

## 8. Критерии успеха

| Проверка | Порог |
|---|---|
| all всего | ≥ 16/18 |
| одиночный слой, свои | ≥ 5/6 |
| одиночный слой, чужие | ≤ 1/6 |
| очистка, свои | ≤ 1/6 |
| очистка, чужие | ≥ 5/6 |
| `total(full) − total(all)` | > 0 |
| ΔLTM/ΔWM/ΔSTM | > 0, сходится с блоками ±10 % |
| секреты в файлах/аудите | 0 |

Порог не выполнен — не подгонять фикстуру, а смотреть prompt/retrieval/route
и зафиксировать причину.

## 9. Порядок выполнения

### TUI

1. `cargo run -- --data-dir ./data tui`.
2. Настройки (6): модель, бюджеты, Local.
3. «Память» → импорт facts (`fixtures/day10-facts.json`) или экран
   «Проверка» → «Загрузить фикстуру».
4. Проверить: STM 34/окно 8, WM 7, LTM 15, pending 1.
5. «Проверка» (3) → `quick` (9 вопросов: S1,S3,S5,W1,W3,W5,L1,L3,L5).
6. `full` → 7×18 = 126 запросов.
7. Включить очистку → +54, всего 180.
8. `s` — сохранить `docs/results/experiment-YYYY-MM-DD.md` и `.json`.
9. Заполнить выводы по шаблону.

### CLI

```sh
cargo run -- --data-dir ./data import-facts fixtures/day10-facts.json
cargo run -- --data-dir ./data experiment --quick
cargo run -- --data-dir ./data experiment --full \
  --out docs/results/experiment-2026-11-17.md \
  --json docs/results/experiment-2026-11-17.json \
  --check
```

Код выхода `--check`: `0` — пороги пройдены, `4` — нет.

Ориентировочная стоимость DeepSeek: 180 × ~2000 prompt ≈ $0.10–0.20.
`quick` — вдвое меньше.

### Автотесты

Fake-клиент отвечает `expected`, если нужный блок есть в промпте, иначе
`не знаю`. Проверяется механика, не качество модели:

- блок присутствует только в своей конфигурации;
- счётчики совпадают с матрицей;
- очистка убирает ровно свой блок;
- токены и дельты положительны;
- Markdown содержит таблицы.

## 11. Интерпретация

| Наблюдение | Вывод |
|---|---|
| слой отвечает на чужие вопросы | утечка/дубликаты в фикстуре |
| свои падают при наличии слоя | retrieval/бюджет/рендер; смотреть dropped/notes |
| all хуже full | потери извлечения/усечения; зафиксировать цену |
| Δ отрицательна | ошибка измерения/блок не включён |
| очистка ломает больше своего | скрытая зависимость |
| всё «не знаю» | ключ/модель/пустой промпт |
