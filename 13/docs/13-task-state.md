# День 13. Состояние задачи (Task State Machine)

## 1. Задача

Поверх ассистента Дня 12 добавить явное состояние задачи:

1. этап задачи;
2. текущий шаг;
3. ожидаемое действие;
4. допустимые переходы между этапами;
5. проверку перехода кодом **до** применения, а не только инструкцией в промпте.

Маршрут:

```text
planning → execution → validation → done
```

Примеры запретов:

- нельзя начинать реализацию до утверждённого плана;
- нельзя объявлять финал без пройденной валидации;
- нельзя перепрыгнуть этап (`planning → validation` запрещён).

## 2. Доменная модель

`src/domain/task.rs`:

```rust
pub enum TaskStage { Planning, Execution, Validation, Done }
pub enum TaskStatus { Idle, Running, Paused, Done, Failed }

pub struct TaskState {
    pub goal: String,
    pub stage: TaskStage,
    pub status: TaskStatus,
    pub step_index: usize,
    pub step_total: usize,
    pub current_step: String,
    pub expected_action: String,
    pub plan: Option<String>,
    pub plan_approved: bool,
    pub execution: Option<String>,
    pub validation: Option<String>,
    pub validation_passed: Option<bool>,
    pub error: Option<String>,
    pub history: Vec<TaskTransitionRecord>,
    // id, version, created_at, updated_at
}
```

`TaskState::can_transition` проверяет переход, `TaskState::transition` применяет
его только после успешной проверки. Каждый переход пишется в `history`.

## 3. Разрешённые переходы

| Из | В | Предусловие в коде |
|---|---|---|
| — | `planning` | задача запущена |
| `planning` | `execution` | план записан, содержит ≥ 2 шага и утверждён (`plan_approved`) |
| `execution` | `validation` | результат реализации не пуст |
| `validation` | `done` | вердикт `ВЕРДИКТ: OK`, `validation_passed = true` |
| `validation` | — (статус `failed`) | вердикт `FAIL`; этап остаётся `validation` |
| `done` | — | терминальное состояние |

Все остальные переходы возвращают `TaskTransitionError`:

- `StageSkipped` — попытка перепрыгнуть этап;
- `PlanNotApproved` — реализация без утверждённого плана;
- `ExecutionIncomplete` — валидация без результата;
- `ValidationNotPassed` — финал без успешной проверки;
- `AlreadyDone` — изменения после завершения.

## 4. Исполнение агентом

`src/task/runner.rs::run_task` делает три запроса к LLM — по одному на этап:

1. **planning** — план; код проверяет, что в плане минимум два шага, и только
   затем утверждает его;
2. **execution** — реализация утверждённого плана;
3. **validation** — проверка результата; модель обязана вернуть
   `ВЕРДИКТ: OK` или `ВЕРДИКТ: FAIL`.

Переходы выполняет только код. Ответ модели заполняет артефакт текущего этапа,
но не может изменить этап, пропустить проверку или завершить задачу.
При `FAIL` задача остаётся на `validation` со статусом `failed`.

Все три HTTP-запроса попадают в общий API-журнал (`вкладка 6`) через
`RecordingChatClient`.

## 5. Пауза и продолжение

- `p`/`Space` на вкладке «Состояния» переключают паузу.
- В TUI пауза видна сразу: статус `пауза`, подпись в строке ввода.
- Worker-поток проверяет флаг паузы между запросами и ждёт снятия паузы,
  не блокируя TUI.
- `q`/`Ctrl+C` отменяют ожидание и завершают job.

## 6. TUI: вкладка «8 Состояния»

```text
┌ Маршрут ──────────────────────────────────────────────────────────┐
│ [1 planning] → [2 execution] → [3 validation] → [4 done]          │
│ Этап: Выполнение · шаг 1/1 · статус: выполняется                  │
│ Текущий шаг: Выполнение плана                                      │
│ Ожидаемое действие: Выполнить утверждённый план…                  │
├ Состояние задачи ─────────────────────────────────────────────────┤
│ Задача: подготовить отчёт                                          │
│ План: утверждён                                                   │
│ — План —                                                          │
│   1. Собрать данные                                               │
│   2. Подготовить отчёт                                            │
│ …                                                                 │
├ Новая задача ─────────────────────────────────────────────────────┤
│ > введите задачу и нажмите Enter                                  │
└───────────────────────────────────────────────────────────────────┘
```

- `i`/`Enter` — захватить поле ввода задачи;
- `Enter` в поле — запустить задачу агентом;
- `p`/`Space` — пауза/продолжить;
- `↑↓`, `PgUp/PgDn`, `g/G` — прокрутка деталей;
- пока задача активна, новая задача не запускается.

## 7. Тесты
