# ai-advent-challenge-09 — 12.11.2026

Агент с **управлением контекстом**: последние N сообщений уходят в модель как
есть, более старая часть истории заменяется отдельной **сводкой (summary)**.
Токены считаются до и после сжатия, поэтому видно, сколько экономит компрессия
и какие детали при этом теряются.

Сделано на основе [08](../08): тот же агент с tool-calling, токенами, стоимостью,
localStorage и журналом API. Добавлены планировщик сжатия, генератор сводки,
отдельное хранилище summary, вкладка «Память» и контрольный диалог из 24
сообщений с 12 проверяемыми деталями.

Стек: **Vite 8 + Vue 3 + TypeScript**, OpenAI-совместимый Chat Completions API.
Тесты — Vitest.

## Как работает сжатие

Параметры задаются в «Настройках» → «Управление контекстом»:

- **последних сообщений как есть** — по умолчанию `8`;
- **сжимать каждые N старых сообщений** — по умолчанию `10`;
- **режим сводки** — `LLM` (отдельный запрос к модели) или `local`
  (локальная выжимка без API);
- сжатие можно полностью выключить.

Алгоритм перед каждым запуском агента:

```text
1. Отбросить system и починить незавершённые tool_calls.
2. Найти начало «свежего» окна: последние N сообщений,
   выровненные по границе user-сообщения.
3. Всё, что старше окна и ещё не входит в сводку, — кандидат на сжатие.
4. Если кандидатов >= M, обновить сводку: previous summary + новая порция.
5. В модель отправить: основной system + summary + неохваченный остаток.
6. Полную историю сохранить в localStorage без изменений.
```

Окно выравнивается по `user`-сообщению, чтобы не разорвать пару
`assistant(tool_calls) → tool`: Chat Completions API требует ровно один
tool-результат на каждый `tool_call`.

Полная история никогда не удаляется. В запрос уходит только «представление»:

```json
{
  "messages": [
    { "role": "system", "content": "Ты — агент с инструментами…" },
    {
      "role": "system",
      "content": "Сводка предыдущей части диалога (16 сообщений, обновлений: 2):\n- П: …\n- А: …"
    },
    { "role": "user", "content": "…последнее из свежего окна…" },
    { "role": "assistant", "content": "…" },
    { "role": "user", "content": "Новый вопрос" }
  ]
}
```

### Два режима сводки

| | `LLM` | `local` |
|---|---|---|
| Как строится | отдельный запрос к модели | эвристическая выжимка |
| Стоимость | тратит prompt/completion токены | 0 токенов |
| Что сохраняет | переформулирует, старается удержать факты | дословно сообщения пользователя, ответы ассистента сокращает до 80 символов |
| Риск | может пропустить число или имя | теряет нюансы ответов ассистента |
| Когда полезен | длинные диалоги, сложные формулировки | демо без ключа, экономия на самом сжатии |

Промпт LLM-сжатия отдельно требует сохранять имена, даты, сроки, бюджеты,
ограничения, решения, риски и открытые вопросы. Это не гарантия: модель может
потерять деталь, поэтому в приложении есть контрольный диалог и проверка памяти.

## Где хранится сводка

Полная история и сводка — **два разных ключа**:

```text
lab09.conversation.v1   → { version, id, createdAt, updatedAt, messages: [...] }
lab09.summary.v1        → { version, conversationId, text, coveredMessages, updatedAt, mode, chunks }
```

Пример сводки:

```json
{
  "version": 1,
  "conversationId": "conversation-…",
  "text": "- П: Дедлайн проекта — 15 декабря 2026 года…\n- А: Принято.",
  "coveredMessages": 16,
  "updatedAt": "2026-11-15T12:00:00.000Z",
  "mode": "local",
  "chunks": 1
}
```

`coveredMessages` — сколько сообщений с начала истории уже вошло в сводку. Это
позволяет обновлять её инкрементально и не сжимать одно и то же повторно.
При сбросе или импорте истории сводка очищается: старый `coveredMessages`
нельзя применять к другому массиву сообщений.

Экспорт истории включает summary отдельным полем, но импорт читает только
`messages` и начинает память заново — это осознанно, чтобы не подмешать сводку
от другой беседы.

## Экономия токенов

Вкладка «Токены» показывает:

- **полная история** — оценка всех `messages` без system и tools;
- **в запросе** — summary + последние N сообщений;
- **сводка** — сколько токенов занимает сам текст summary;
- **экономия** — разница и процент;
- **запросы на сжатие** — сколько HTTP-запросов и денег ушло на построение
  сводки (для `LLM`-режима).

Формула экономии на одном запросе:

```text
saved = full_history_tokens − (summary_tokens + tail_tokens)
net   = saved − summary_request_tokens
```

Важно: LLM-сжатие — это тоже запрос, он стоит токенов. Если диалог короткий,
сжатие может не окупиться. Порог `M` и размер окна `N` — компромисс между
точностью памяти и стоимостью.

Приблизительный локальный расчёт на контрольном диалоге из 24 сообщений:

| Метрика | Без сжатия | Со сжатием (`local`) |
|---|---:|---:|
| История | 1 093 токена | 926 токенов |
| Детали в контексте | 12 / 12 | 12 / 12 |
| Экономия prompt | — | ~167 токенов (~15%) |
| Запросы на сжатие | 0 | 0 |

Цифры зависят от эвристики токенов и текста диалога; в интерфейсе они
пересчитываются на реальной истории. LLM-сводка обычно короче локальной, но
добавляет стоимость одного запроса на каждую порцию.

## Проверка памяти: что потерялось

В приложении есть готовый контрольный диалог: **24 сообщения**, в первых
12 спрятаны **12 конкретных деталей**, последние 8 сообщений — «шум» без фактов.
Если оставить последние 8 как есть, все детали может сохранить только сводка.

Список деталей составлен заранее:

| Категория | Деталь | Вопрос после сжатия |
|---|---|---|
| имя | Проект «Атлас» | Как называется проект? |
| имя | Заказчик — Марина Ковалёва | Как зовут заказчика? |
| срок | Дедлайн — 15 декабря 2026 | Какой дедлайн? |
| бюджет | 480 000 рублей | Какой бюджет? |
| ограничение | Только российские ЦОД | Какое ограничение по инфраструктуре? |
| имя | Тимлид — Артём Соколов | Кто тимлид? |
| ограничение | 4 разработчика | Сколько разработчиков? |
| срок | Прототип — 3 ноября 2026 | Когда прототип? |
| решение | PostgreSQL | Какую БД выбрали? |
| решение | REST, не GraphQL | Какой стиль API? |
| бюджет | 120 000 рублей на маркетинг | Сколько на маркетинг? |
| срок | Релиз — 20 декабря 2026 | Когда релиз? |

### Как запустить проверку

1. Открой вкладку «Память».
2. Нажми **«Загрузить контрольный диалог»** — появится 24 сообщения.
3. Нажми **«Сжать сейчас»** (или задай любой вопрос агенту: сжатие сработает
   автоматически, потому что старых сообщений 16 >= порога 10).
4. Нажми **«Проверить оба режима»** — приложение задаст 12 вопросов дважды:
   с полной историей и с summary + последними 8 сообщениями.
5. Сравни таблицу: для каждой детали видно ответы модели и отметки
   «вспомнил / не вспомнил».

Что показывает отчёт:

- **без сжатия** и **со сжатием** — сколько деталей из 12 вспомнила модель;
- **экономия prompt** — разница токенов на вопросы;
- **с учётом сжатия** — экономия минус токены, потраченные на построение сводки;
- **ответы модели** — раскрываются у каждой детали, чтобы видеть формулировки.

Локальная проверка (без API) показывает, какие детали вообще остались в
контексте после сжатия. Это полезно, но не заменяет реальный прогон: модель
может ответить «не знаю» даже при наличии факта в промпте или наоборот
угадать ответ.

Ожидаемое поведение:

- без сжатия модель видит все 24 сообщения и обычно вспоминает 12/12;
- с `local`-сводкой все детали из пользовательских сообщений сохраняются
  дословно — чаще всего тоже 12/12, но контекст короче;
- с `LLM`-сводкой возможны потери: модель может опустить число, имя или
  ограничение. Это и есть ответ на вопрос «что потерялось»;
- чем больше `keepRecent`, тем выше точность и ниже экономия; чем меньше —
  наоборот.

## Сценарии проверки

### 1. Сжатие без API

1. «Память» → «Загрузить контрольный диалог».
2. «Настройки» → режим `local`.
3. «Память» → «Сжать сейчас».
4. Смотри «полная история / в запросе / экономия» и список деталей:
   все 12 должны остаться в контексте.

### 2. Сжатие через LLM

1. Укажи API-ключ и модель.
2. Режим `LLM`, «Сжать сейчас» или отправь реплику.
3. Во вкладке «API» появится запрос с бейджем `summary` — это отдельный
   расход токенов, он учтён в «Токенах».

### 3. Длинный диалог

1. Продолжай диалог 20–30 сообщений.
2. Сводка обновляется порциями по 10 старых сообщений.
3. Полная история растёт, а контекст запроса остаётся ограниченным:
   summary + последние 8 + новое сообщение.

### 4. Выключенное сжатие

1. «Настройки» → снять «Сжимать старую часть истории».
2. Агент снова отправляет всю историю, как в дне 08.
3. В «Токенах» экономия будет нулевой — удобно сравнить.

## Тесты

```sh
npm test -w 09
```

Тесты без реального API-ключа:

- окно последних N сообщений выравнивается по `user` и не рвёт tool-пары;
- сжатие не срабатывает ниже порога и срабатывает при накоплении;
- локальная сводка сохраняет все 12 контрольных деталей;
- сводка обновляется инкрементально и не сжимает одно и то же повторно;
- Agent отправляет `summary` вместо старых сообщений, но возвращает полную
  историю для сохранения;
- сломанный LLM-генератор откатывается на локальную выжимку;
- 24-сообщенный диалог содержит 12 деталей, последние 8 сообщений — без них;
- сравнение «полная история vs сжатие» уменьшает prompt-токены и сохраняет
  ответы модели на замоканном API;
- отдельное хранилище сводки: сохранение, загрузка, очистка, битый JSON;
- прежние тесты 08: tool-loop, токены, стоимость, переполнение, localStorage.

## Как устроено

```text
src/

    Agent.ts          # tool-loop + сборка prompt из summary + tail
    compression.ts    # план сжатия, summary, локальная выжимка, метрики
    summarizer.ts     # LLM-запрос на сводку + usage
    history.ts        # починка незавершённых tool_calls
    ToolRegistry.ts   # схемы инструментов, вызов, обработка ошибок
  api/
    llm.ts            # HTTP-клиент + распознавание context_length_exceeded
  storage/
    conversation.ts   # полная история: JSON, валидация, localStorage
    summary.ts        # отдельный JSON сводки в lab09.summary.v1
  memory/
    dialog.ts         # контрольный диалог, 12 деталей, проверка совпадений
    benchmark.ts      # 12 вопросов × 2 режима, токены и стоимость
  tokens.ts           # оценка токенов, профили, стоимость, сценарии
  tools/
    time.ts           # get_current_time
    calculator.ts     # calculate
    currency.ts       # convert_currency
  components/
    SettingsPanel.vue # провайдер, параметры, сжатие, лимит контекста
    MessageBubble.vue # сообщения, trace вызовов, ↑prompt ↓completion
    HistoryPanel.vue  # полная история, JSON, ключи хранения
    TokenPanel.vue    # сжатие, контекст, стоимость, рост, сценарии
    ContextPanel.vue  # summary, детали, проверка памяти
    ApiLogPanel.vue   # журнал запросов, включая summary
  App.vue             # состояние чата, сохранение, запуск агента и benchmark
```

`Agent` не знает про localStorage. Он получает полную историю, применяет
`compressHistory`, отправляет подготовленный контекст и возвращает:
- новую сводку;
- статистику сжатия;
- полную историю с новыми сообщениями.

`App.vue` сохраняет историю и сводку раздельно. `ContextPanel.vue` показывает
summary, проверяет наличие деталей в полном и сжатом контексте и запускает
реальную проверку через `benchmark.ts`.

## Ограничения

- Сводка — это потеря информации по определению; проверяйте важные детали.
- LLM-сводка стоит токенов и может сама ошибиться или пропустить факт.
- Локальная выжимка дословно сохраняет пользовательские сообщения, поэтому
  экономия на коротких репликах небольшая; кроме того, она накапливается
  линейно. Для очень длинных диалогов лучше LLM-режим, который пересобирает
  сводку целиком.
- Оценка токенов приблизительная: точное значение зависит от токенизатора.
- Порог сжатия задаётся числом сообщений, а не токенов; очень длинные
  сообщения могут переполнить окно даже после сжатия.
- Одна беседа и одна сводка на браузер (два ключа localStorage).
- Журнал HTTP-запросов и `usage` живут только в памяти текущей сессии.
- Проверка памяти использует ключевые слова, а не семантическую оценку:
  ответ «480 тыс. ₽» будет засчитан, а необычная формулировка — нет.
- Нет стриминга: ответ приходит целиком после каждого запроса.
