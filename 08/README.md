# ai-advent-challenge-08 - 11.11.2026

Агент с tool-calling, сохранением контекста **и подсчётом токенов**. Для каждого
запроса видно, сколько токенов уходит на system-промпт, историю, новое сообщение и
схемы инструментов, сколько токенов вернула модель и во сколько это обошлось.
Если диалог не влезает в контекстное окно, агент всё равно **отправляет запрос** и
показывает реальный ответ провайдера или его ошибку переполнения.

Сделано на основе [07](../07): тот же цикл tool-calling, инструменты, интерфейс и
сохранение истории. Добавлены оценка токенов, стоимость, профили моделей, диагностика
переполнения и вкладка «Токены».

Стек: **Vite 8 + Vue 3 + TypeScript**, OpenAI-совместимый Chat Completions API.
Тесты — Vitest.

## Как считаются токены

Точное число токенов знает только токенизатор модели. В браузере BPE-словарь не
нужен, поэтому используется оценка по составу текста (`src/tokens.ts`):

```text
tokens ≈ кириллица / 2
       + латиница и цифры / 3.8
       + пунктуация / 2.5
       + пробелы / 14
       + широкие символы (эмодзи) × 2
```

К каждому сообщению добавляются служебные токены формата Chat Completions:
роль, `tool_call_id`, имя инструмента, `tool_calls` и их аргументы. Схемы
инструментов считаются как JSON и тоже входят в каждый промпт.

Оценка нужна, чтобы:

- увидеть порядок величин до отправки;
- заранее поймать переполнение;
- сравнить сценарии без реальных запросов и без ключа.

После ответа провайдера приоритет получает точный `usage`:

```json
"usage": {
  "prompt_tokens": 812,
  "completion_tokens": 96,
  "total_tokens": 908
}
```

Если провайдер не вернул `usage`, интерфейс честно помечает значения как оценку.

### Три уровня подсчёта

1. **Текущий запрос** — карточки `prompt`, `ответ`, `всего`, `стоимость` во
   вкладке «Токены». Для последнего запроса показываются `prompt_tokens` и
   `completion_tokens` из `usage`, а до отправки — локальная оценка.
2. **Вся история диалога** — `history` в блоке «Вся история и стоимость сессии»:
   оценка текущего массива `messages` без system и без схем инструментов.
3. **Сумма по сессии** — `prompt sum` и `cost`: все запросы, включая каждую
   итерацию tool-loop. Важно: каждый шаг отправляет историю заново, поэтому сумма
   prompt-токенов растёт быстрее, чем сама история.

## Стоимость

Цены берутся из профиля модели и являются ориентировочными:

| Профиль | Контекст | Цена входа за 1M | Цена выхода за 1M |
|---|---:|---:|---:|
| DeepSeek (`deepseek-*`) | 128 000 | $0.28 | $0.42 |
| Moonshot / Kimi (`kimi-*`) | 256 000 | $0.60 | $2.50 |
| Другая OpenAI-совместимая | 128 000 | $0.50 | $1.50 |

Формула:

```text
cost = prompt_tokens  / 1_000_000 * inputUsdPerMillion
     + completion_tokens / 1_000_000 * outputUsdPerMillion
```

Точную сумму всегда считает биллинг провайдера. Здесь — оценка, чтобы увидеть,
как растёт цена по мере диалога.

Лимит контекста можно переопределить в «Настройках»:

- пусто — берётся из профиля модели;
- например `2000` — удобно воспроизвести переполнение на коротком диалоге,
  не генерируя сотни тысяч токенов.

## Что происходит при переполнении

Chat Completions API принимает **один промпт целиком**: system + вся история +
tools. У модели есть контекстное окно, и если сумма больше него, запрос не может
быть обработан.

Агент считает оценку перед каждой итерацией и показывает разбивку
`system + история + новое сообщение + инструменты`, лимит и процент. Даже если
`totalTokens > limit`, запрос всё равно отправляется: провайдер либо ответит, либо
вернёт `context_length_exceeded`.

Если провайдер отклоняет запрос:

- ответа нет, диалог застревает на ошибке;
- увеличивать `max_tokens` бесполезно — это лимит **ответа**, а не входа;
- автоматического удаления старых сообщений нет: история сохраняется как есть,
  чтобы ничего не потерять незаметно.

Лечение:

- начать новый диалог;
- удалить старые реплики из истории;
- сократить результаты инструментов;
- выбрать модель с большим окном;
- увеличить лимит в настройках, если он был занижен вручную.

## Вкладка «Токены»

- **Контекстное окно** — gauge, статус `влезает / близко к лимиту / переполнено`,
  занято в токенах и процентах, свободный остаток.
- **Разбивка** — `system`, `история`, `новое`, `инструменты`.
- **Текущий запрос и ответ** — `prompt`, `completion`, `total`, стоимость.
- **Вся история и стоимость сессии** — `history`, число запросов, сумма
  `prompt`/`completion`, суммарная стоимость.
- **Рост промпта по запросам** — таблица и полоски по каждой итерации: видно, как
  каждый следующий запрос становится дороже.
- **Сравнение сценариев** — короткий, длинный и переполненный диалог. Считается
  локально, без API.
- **Что ломается при переполнении** — краткое объяснение и способы лечения.

Дополнительно:

- в шапке — `~N tok · %` с цветом статуса, клик открывает вкладку «Токены»;
- у каждой итерации в сообщении — `↑prompt ↓completion`;
- во вкладке «API» — оценка до отправки, точный `usage`, стоимость и полный JSON;
- экспорт журнала API включает профиль модели, текущую оценку контекста и сводку
  по токенам.

## Как хранится контекст

История лежит в `localStorage` под ключом `lab08.conversation.v1`. Это обычный
JSON-снимок:

```json
{
  "version": 1,
  "id": "conversation-…",
  "createdAt": "2026-11-14T10:00:00.000Z",
  "updatedAt": "2026-11-14T10:01:00.000Z",
  "messages": [
    { "role": "user", "content": "Сколько будет 1234 * 56 + 78?" },
    {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_1",
          "type": "function",
          "function": {
            "name": "calculate",
            "arguments": "{\"expression\":\"1234*56+78\"}"
          }
        }
      ]
    },
    {
      "role": "tool",
      "tool_call_id": "call_1",
      "name": "calculate",
      "content": "{\"ok\":true,\"result\":{\"result\":69182}}"
    },
    { "role": "assistant", "content": "Получается 69 182." }
  ]
}
```

Системный промпт не сохраняется: он подставляется заново при каждом запуске.
Сохраняется именно контекст диалога, поэтому смена модели или системного промпта
не ломает загрузку.

Токены не сохраняются в JSON отдельно: они пересчитываются из `messages` при
загрузке. `usage` хранится только в журнале API текущей сессии.

### Что происходит при перезапуске

1. При старте `App.vue` читает JSON из `localStorage` и валидирует его.
2. Из массива `messages` восстанавливается UI-лента, включая trace вызовов
   инструментов.
3. Токены истории сразу пересчитываются заново — gauge показывает актуальное
   заполнение контекста.
4. При следующей реплике весь восстановленный массив уходит в модель вместе с
   новым `user`-сообщением.
5. Если приложение было закрыто между `assistant(tool_calls)` и `tool`-ответом,
   `repairToolCallSequence()` добавит недостающие tool-сообщения.

## Сценарии проверки

### 1. Короткий диалог

1. `npm run dev -w 08`, открой http://localhost:5173/.
2. Спроси: **«Объясни в двух предложениях, чем HTTP отличается от HTTPS»**.
3. Открой «Токены»: маленький `prompt`, немного `completion`, gauge почти пустой.

### 2. Длинный диалог

1. Продолжай задавать вопросы 10–20 раз.
2. Смотри, как растут `history`, `prompt sum` и `cost`.
3. Обрати внимание: каждый новый запрос отправляет всю историю заново, поэтому
   суммарные токены растут быстрее, чем сама история.

### 3. Переполнение

Самый быстрый способ — занизить лимит:

1. «Настройки» → «Лимит контекста, токенов» → `2000`.
2. Задай несколько вопросов, пока оценка не приблизится к лимиту.
3. Отправь ещё одну реплику.
4. Агент всё равно сделает HTTP-запрос: провайдер либо ответит, либо вернёт
   ошибку переполнения с разбивкой `system + история + новое + инструменты` и
   процентом переполнения.
5. Верни лимит пустым — индикатор снова будет показывать нормальное заполнение.

Без изменения настроек те же три сценария видны в блоке «Сравнение сценариев»:
он строит короткую, длинную и переполненную историю локально и показывает
токены, процент лимита, стоимость и ожидаемый результат.

## Как устроено

```text
src/
  agent/
    Agent.ts          # tool-loop + оценка контекста + tokenStats
    history.ts        # починка незавершённых tool_calls
    ToolRegistry.ts   # схемы инструментов, вызов, обработка ошибок
  api/
    llm.ts            # HTTP-клиент + распознавание context_length_exceeded
  storage/
    conversation.ts   # JSON-снимок, валидация, localStorage, восстановление UI
  tokens.ts           # оценка токенов, профили моделей, стоимость, сценарии
  tools/
    time.ts           # get_current_time
    calculator.ts     # calculate + безопасный парсер выражений
    currency.ts       # convert_currency
  components/
    SettingsPanel.vue # провайдер, ключ, параметры, лимит контекста, инструменты
    MessageBubble.vue # сообщения, trace вызовов, ↑prompt ↓completion
    HistoryPanel.vue  # статистика, JSON, экспорт/импорт/очистка
    TokenPanel.vue    # контекст, стоимость, рост, сравнение сценариев
    ApiLogPanel.vue   # журнал запросов/ответов с usage и оценкой
  App.vue             # состояние чата, загрузка/сохранение, запуск агента
```

`Agent` не знает про localStorage: он получает историю и отдаёт каждое новое
сообщение через `onMessageAppended`. `App.vue` дописывает сообщения в канонический
массив и сохраняет JSON. Оценка контекста живёт в `tokens.ts` и используется и
агентом (диагностика), и интерфейсом (gauge).

## Ограничения

- Оценка токенов приблизительная: точное значение зависит от токенизатора модели.
- Цены и лимиты в профилях ориентировочные; проверяй актуальные у провайдера.
- Одна сохранённая беседа на браузер (один ключ `localStorage`).
- Лимит `localStorage` — обычно около 5 МБ; очень длинные диалоги могут упереться
  в квоту.
- Журнал HTTP-запросов и `usage` хранятся только в памяти текущей сессии.
- Автоматического сжатия/обрезки истории нет: при переполнении провайдер может
  вернуть ошибку, а решение остаётся за пользователем.
- Нет стриминга: ответ приходит целиком после каждого запроса.
